# Publique na sua conta do GitHub

## 1. Teste antes de publicar

Extraia o ZIP, entre na pasta `controle-de-chamados` e execute `iniciar.bat` ou `py app.py`. Use os exemplos fictícios e confira o fluxo descrito no README.

## 2. Crie o repositório

Acesse [github.com/new](https://github.com/new) e preencha:

| Campo | Preenchimento |
| --- | --- |
| Owner | `matheusartismo` |
| Repository name | `controle-de-chamados` |
| Description | Projeto de estudo em Python para registrar chamados, acompanhar status e exportar relatórios em CSV. |
| Visibility | Public, para que o código possa ser visto no portfólio. |
| Add README | Deixe desativado, pois o projeto já inclui `README.md`. |
| Add .gitignore | Deixe sem modelo, pois o arquivo já acompanha o projeto. |
| License | Não é necessário selecionar uma licença nesta etapa. |

Clique em **Create repository**.

## 3. Envie os arquivos

Na página inicial do repositório vazio, procure o link **uploading an existing file**. Se o repositório já mostrar uma lista de arquivos, use **Add file → Upload files**.

Envie os arquivos que estão DENTRO da pasta extraída, incluindo `app.py`, `chamados.py`, os arquivos Markdown, `.gitignore`, `iniciar.bat` e a pasta `tests`.

O arquivo `README.md` deve ficar na raiz do repositório, ao lado de `app.py`. Envie os arquivos extraídos, não o arquivo ZIP. Se você já usou o aplicativo, a pasta `dados` é de uso local e deve ficar fora do envio. Ao usar upload pelo navegador, o `.gitignore` não filtra os arquivos que você arrasta manualmente.

Confira a lista e clique em **Commit changes**. Uma mensagem possível é: `Adiciona versão inicial do projeto de estudo`.

## 4. Confira a apresentação

Abra a página principal do repositório. O README deverá aparecer abaixo da lista de arquivos. Confira se os links e as instruções estão legíveis.

Teste novamente a cópia publicada depois de baixá-la. Para dar destaque, você pode fixar este repositório no seu perfil pela opção **Customize your pins**, quando ela estiver disponível.

## 5. Registre sua evolução

Faça uma melhoria de cada vez, teste e crie um commit que explique o que mudou. O arquivo `APRENDA.md` sugere primeiras alterações que você pode entender e apresentar numa entrevista.
